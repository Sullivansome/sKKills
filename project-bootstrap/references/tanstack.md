# TanStack setup (Start / Router / Query)

TanStack projects are Vite-based Node/TS apps. Read `node-ts.md` for the base toolchain — this file covers the TanStack-specific bits.

## What to detect

- `@tanstack/react-start` → TanStack Start (full-stack framework, file-based routing, server functions)
- `@tanstack/react-router` → SPA with file-based or code-based routing
- `@tanstack/react-query` → data layer only; treat as a plain Vite/React app

Scaffold new: `pnpm create @tanstack/start` (Start) or `pnpm create vite` + add Router/Query.

## Lint + format + typecheck

Biome works well here (the TanStack ecosystem itself uses it). Two gotchas:

- **File-based routes are generated.** `routeTree.gen.ts` is auto-generated by the Router/Start plugin — exclude it from lint and format (`biome.json` `files.ignore` or eslint ignore), but DO typecheck it. If formatting fights the generator on every dev run, that's the missing ignore.
- **Type safety is the product.** Router's magic (typed params, search schemas, loaders) lives in the type system, so `tsc --noEmit` is non-negotiable and must run with the generated route tree present. Run `vite dev` once (or `tsr generate`) before typecheck in CI, or the generated file won't exist.

## Tests

Vitest (Start ships Vite config already — vitest plugs straight in). Server functions can be unit-tested as plain async functions.

## CI

Standard Node CI; add a step that generates the route tree before typecheck if routes are file-based:

```yaml
- run: pnpm install --frozen-lockfile
- run: pnpm exec tsr generate   # or rely on vite plugin during build
- run: pnpm format:check && pnpm lint && pnpm typecheck && pnpm test && pnpm build
```

## Release

Web app → deploy flow (Vercel/Netlify/Cloudflare), tags for versioning. Only use `release.md` if the app is wrapped in Tauri/Electron.
