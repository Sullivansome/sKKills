# TanStack setup (Start / Router / Query)

Inspect the host framework and build tool; TanStack Query and Router do not by themselves imply Vite. Read `node-ts.md` for the base toolchain — this file covers the TanStack-specific bits.

## What to detect

- `@tanstack/react-start` → TanStack Start (full-stack framework, file-based routing, server functions)
- `@tanstack/react-router` → SPA with file-based or code-based routing
- `@tanstack/react-query` → data layer only; preserve the host framework and tooling

Scaffold new: `pnpm create @tanstack/start` (Start) or `pnpm create vite` + add Router/Query.

The route-generation advice below applies only when file-based Router/Start routing is actually configured. Query-only usage adds no route-generation requirement, and a scoped Router dependency alone does not prove file-based routing. Preserve the host framework's setup and inspect routing configuration before adding a generator.

## Lint + format + typecheck

Biome works well here (the TanStack ecosystem itself uses it). Two gotchas:

- **File-based routes are generated.** `routeTree.gen.ts` is auto-generated by the Router/Start plugin — exclude it from lint and format (use the installed tool's schema: Biome v2 `files.includes` exclusions, or ESLint ignores), but DO typecheck it. If formatting fights the generator on every dev run, that's the missing ignore.
- **Type safety is the product.** Router's magic (typed params, search schemas, loaders) lives in the type system, so `tsc --noEmit` is non-negotiable and must run with the generated route tree present. Use a terminating generation command before typecheck in CI. If using `tsr generate`, install and pin the compatible `@tanstack/router-cli` and verify its configuration. Do not start a persistent dev server as a CI generation step.

## Tests

Vitest (Start ships Vite config already — vitest plugs straight in). Server functions can be unit-tested as plain async functions.

## CI

Standard Node CI; add a step that generates the route tree before typecheck if routes are file-based:

```yaml
- run: pnpm install --frozen-lockfile
- run: pnpm exec tsr generate   # requires a compatible pinned router CLI; adapt for Start
- run: pnpm format:check && pnpm lint && pnpm typecheck && pnpm test && pnpm build
```

## Release

Web app → deploy flow (Vercel/Netlify/Cloudflare), tags for versioning. Only use `release.md` if the app is wrapped in Tauri/Electron.
